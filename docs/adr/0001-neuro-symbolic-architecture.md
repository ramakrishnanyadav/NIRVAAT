# ADR 0001: Neuro-Symbolic Architecture for High-Stakes Public Health Advice

## Status
Accepted

## Context
During severe winter inversion smog episodes in Delhi NCR and global urban basins, ambient PM2.5 levels exceed hazardous thresholds (>250 µg/m³). Families and vulnerable individuals make critical daily decisions: whether to seal windows, when to ventilate, how to time outdoor commutes, and when to use purifiers or masks.

When general-purpose Large Language Models (LLMs) are tasked directly with numeric air quality calculations or health recommendations, they exhibit well-documented failure modes:
1. **Hallucinated numbers**: Emitting fabricated percentage exposure reductions (e.g., claiming a window tweak cuts 80% of dose when physics permits only 12%).
2. **Inconsistent recommendations**: Providing contradictory timing or neglecting microenvironment interactions (e.g., advising window opening during nighttime thermal inversions).
3. **Clinical safety breaches**: Erroneously advising parents to place N95 masks on infants under two years old (suffocation hazard) or misconstruing medication guidance.

## Decision
We adopt a **strict neuro-symbolic architecture**:
1. **Symbolic Core**: All physical impact estimates, steady-state indoor mass balances, Monte Carlo dose distributions, and red-flag symptom detections are computed by deterministic, tested software engines (`@nirvaat/engines` and `@nirvaat/verifier`).
2. **Constrained Neural Layer**: The LLM (Gemini) is restricted to conversational synthesis, linguistic translation (`en-IN` / `hi-IN`), formatting for multiple communication channels (`APP`, `WHATSAPP`, `SMS`, `VOICE`), and empathy.
3. **Zero Direct LLM Arithmetic**: The prompt forbids the model from performing calculations. It must cite numbers generated by deterministic tool calls via structured `tool_ref` tags.
4. **Mandatory Verifier Gate**: All draft model responses are intercepted by a deterministic verifier before leaving the server. If any numeric claim deviates from the underlying engine trace or violates a safety rule, the LLM output is rejected and replaced with a deterministic fallback plan.

## Consequences
### Positive
- **Guaranteed Numeric Integrity**: No fabricated percentages or ungrounded dose numbers reach the user.
- **Fail-Safe Reliability**: If the Gemini API experiences network latency, rate limits, or outage, the application automatically serves a high-fidelity Tier D deterministic plan without service interruption.
- **Auditable Provenance**: Every number displayed to the user can be traced to a specific mass-balance formula and input distribution.

### Negative
- **Server Orchestration Overhead**: Every request requires server-side coordination between tool runs, LLM calls, and verifier passes (~400–900ms depending on model latency).
- **Stricter Prompt & Output Constraints**: The model must conform to strict JSON schemas, requiring schema repair or deterministic fallback when outputs fail schema validation.
